# Технічний аудитор витягів і цитувань

`Language: UK` `Академічні витяги та контроль цитувань` `Source file: ВИТЯГ.md`

## Що це за промпт

Український промпт для витягу й аудиту матеріалів цитування з окремих частин академічної роботи.

## Для чого саме

Використовується для підготовки чистої карти цитувань і перевірки прив'язки джерел до фрагментів тексту.

## Що можна отримати

- Карта цитувань
- Зв'язки джерело-фрагмент
- Технічний аудит цитувань

## Очікувані результати

- Менше непідтверджених посилань
- Зрозуміліше використання джерел
- Легше фінальне очищення бібліографії

## Що підготувати

- Частини академічної роботи
- Список джерел або цитування
- Цільовий обсяг витягу

## Як використовувати

- Відкрийте потрібну мовну версію.
- Скопіюйте блок промпту повністю.
- Додайте файли або посилання, які промпт очікує як вхідні дані.
- Після першого запуску уточніть змінні, які модель попросить конкретизувати.

## Промпт

<details open>
<summary>Текст промпту</summary>

~~~markdown
Ти працюєш як бібліографічний редактор і технічний аудитор цитувань.

Моє завдання: я збираю кваліфікаційну роботу з кількох окремих студентських файлів: курсових робіт, звітів, проєктів і самостійних робіт. У кожному файлі є власні внутрішньотекстові посилання у квадратних дужках, наприклад [1], [2], [3], а також власний список використаних джерел.

Критично важливо:
- не змішуй джерела з іншими файлами;
- працюй тільки з ОДНИМ наданим файлом;
- не вигадуй джерела;
- не змінюй зміст бібліографічних описів без потреби;
- не перенумеровуй джерела у фінальний список;
- не створюй нову бібліографію;
- не замінюй джерела на “схожі”;
- якщо джерело неповне, познач це у коментарі, але не вигадуй відсутні дані.

## Назва файлу для аналізу:
[ВСТАВ НАЗВУ ФАЙЛУ]

## Префікс для унікальних ID:
[ВСТАВ ПРЕФІКС]

Наприклад:
- якщо це курсова робота, можна використати `KURS-SRC`;
- якщо це звіт з практики — `ZVIT-SRC`;
- якщо це проєкт — `PROEKT-SRC`;
- якщо це самостійна робота — `SAM-SRC`;
- якщо це методичні рекомендації — `METOD-SRC`.

## Завдання

Проаналізуй наданий файл і створи Citation Map — карту відповідності між старими внутрішньотекстовими посиланнями та реальними джерелами зі списку використаних джерел цього ж файлу.

Потрібно виконати такі дії:

1. Знайди всі внутрішньотекстові посилання у квадратних дужках:
   - [1]
   - [2]
   - [3]
   - [1, 2]
   - [1–3]
   - [1; 4; 7]
   - інші подібні варіанти.

2. Знайди список використаних джерел у цьому самому файлі.

3. Для кожного джерела зі списку створи унікальний ID у такому форматі:

   `[ПРЕФІКС]-001`, `[ПРЕФІКС]-002`, `[ПРЕФІКС]-003`

   Наприклад:

   `KURS-SRC-001`  
   `KURS-SRC-002`  
   `KURS-SRC-003`

4. Зістав старий номер посилання з відповідним джерелом зі списку використаних джерел.

5. Визнач, де в тексті використовується кожне джерело:
   - Реферат;
   - Вступ;
   - Розділ 1;
   - Розділ 2;
   - Розділ 3;
   - Висновки;
   - Додатки;
   - або інший структурний елемент, якщо він є у файлі.

6. Якщо джерело є у списку літератури, але не використовується в тексті, познач:
   `Не знайдено в тексті`.

7. Якщо посилання є в тексті, але відповідного джерела немає у списку літератури, познач:
   `ПОМИЛКА: джерело відсутнє у списку`.

8. Якщо джерело виглядає неповним, наприклад немає року, назви, URL, автора або видавництва, не виправляй його самостійно, а познач у коментарі:
   `Неповний бібліографічний опис`.

## Формат відповіді

Сформуй відповідь строго у Markdown за такою структурою:

# Citation Map для файлу: [Назва файлу]

## 1. Загальна інформація

| Поле | Значення |
|---|---|
| Назва файлу |  |
| Тип файлу | курсова / звіт / проєкт / самостійна робота / інше |
| Кількість джерел у списку літератури |  |
| Кількість унікальних посилань у тексті |  |
| Префікс ID |  |

## 2. Основна карта джерел

| Старе посилання | Унікальний ID | Повний бібліографічний опис із файлу | Де використовується в тексті | Коментар |
|---|---|---|---|---|
| [1] | [ПРЕФІКС]-001 |  |  |  |
| [2] | [ПРЕФІКС]-002 |  |  |  |
| [3] | [ПРЕФІКС]-003 |  |  |  |

## 3. Посилання, знайдені в тексті

| Посилання в тексті | Розділ / місце використання | Відповідний унікальний ID | Статус |
|---|---|---|---|
| [1] |  |  | підтверджено / проблема |
| [2] |  |  | підтверджено / проблема |

## 4. Джерела зі списку, які не були знайдені в тексті

| Старий номер | Унікальний ID | Бібліографічний опис | Коментар |
|---|---|---|---|

## 5. Проблемні або сумнівні місця

| Проблема | Де знайдено | Коментар |
|---|---|---|
| Посилання є в тексті, але немає джерела у списку |  |  |
| Джерело є у списку, але не використовується в тексті |  |  |
| Бібліографічний опис неповний |  |  |
| Посилання має незрозумілий формат |  |  |

## 6. Готова таблиця для подальшої заміни посилань

Сформуй окрему таблицю, яку можна буде використати для автоматичної або напівавтоматичної заміни старих посилань на унікальні ID.

| Що замінити | На що замінити |
|---|---|
| [1] | [[ПРЕФІКС]-001] |
| [2] | [[ПРЕФІКС]-002] |
| [3] | [[ПРЕФІКС]-003] |

## 7. Короткий висновок

Напиши коротко:
- чи вдалося повністю зіставити всі посилання;
- які проблеми знайдено;
- чи можна цей файл безпечно використовувати для подальшого об’єднання у кваліфікаційну роботу.

Важливо:
не переходь до генерації кваліфікаційної роботи.
Твоє завдання — тільки створити Citation Map для одного конкретного файлу.
~~~
